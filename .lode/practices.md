# Practices

Patterns and practices relevant to this project.

- Chat-mode first - architecture is discussed and settled in chat before code is written (Lode Coding workflow).
- Locked-decisions only - only choices the user states explicitly are treated as decided. Everything else is an open fork recorded in [architecture/open-questions.md](architecture/open-questions.md); analysis may list options and trade-offs but never silently promotes one to a decision.
- Immediate capture - when the user locks a decision, the corresponding architecture lode file is updated before moving on.
- Facts vs inference - lode entries separate observed facts (source: repo, docs, release notes) from inference; inferences are marked. When lode content contradicts code, code wins.
- Parity source of truth - for feature questions, the original tool's repo/docs are the reference: [background/original-tool.md](background/original-tool.md).
- Simplest-possible code - no pre-emptive architecture, no future-proofing; implement exactly what was asked.
- Toolchain - Rust and pnpm versions are pinned in `mise.toml`; CI installs them with `jdx/mise-action`. Run `mise install` after cloning (mise bootstraps rustup for the Rust toolchain).
- Dev loop - `pnpm --dir web dev` for SPA work (a dev-only middleware in `web/vite.config.ts` exports `example/workspace.dsl` with the `structurizr` CLI and serves the result at `/workspace.json`, cached in Vite's cache dir until the DSL changes). To verify the real static output: `pnpm --dir web build`, then `cargo run -- generate --workspace example/workspace.dsl --output build`, then serve `build/` with any static server.
- Lint - Rust: `cargo fmt --check` and `cargo clippy -- -D warnings`. SPA: `pnpm --dir web lint` (oxlint, ships with the Vite template). Commits: conventional commits, enforced by commitlint in CI on pull requests.
- Tests - Rust: `cargo test --locked` (CI runs it after the web build). Unit tests live in `#[cfg(test)]` modules per file; the binary-level test in `tests/cli.rs` fakes `structurizr` with a POSIX shell shim on the child's PATH (unix-only). `cargo test` needs `pnpm --dir web build` to have run first: `RustEmbed` embeds `web/dist` at compile time (a missing folder breaks compilation; an empty one fails `spa` tests at runtime with "SPA bundle is missing index.html"). Integration tests assert on the stable `./assets/` substring, never hashed asset filenames. SPA: `pnpm --dir web test` (CI runs it after the web build) — vitest + React Testing Library + jsdom, configured in `web/vitest.config.ts` (kept separate from `vite.config.ts`, whose `workspaceJson` plugin shells out to `structurizr`; tests mock `fetch`, so the plugin is never needed). Tests are colocated `*.test.{ts,tsx}` files; shared fixtures/helpers live in `web/src/test/`. DOM tests stub `window.matchMedia` via `web/src/test/match-media.ts` (jsdom lacks it) and stub `fetch` with a plain `{ ok, status, json }` object; queries are semantic — roles and accessible names with jest-dom matchers, never class names — and breadcrumb assertions scope with `within(nav)` because `BreadcrumbPage` also carries `role="link"`. `SidebarInset` renders the page's single `<main>` landmark; page content below it must not use `<main>` again (nested `main` is invalid HTML and breaks `getByRole('main')`).
- Changelog - keepachangelog 1.0.0, generated from conventional commits by git-cliff (`cliff.toml`). Release flow: `git cliff --unreleased --prepend CHANGELOG.md`, bump `Cargo.toml`, tag `vX.Y.Z`, push with tags; the release workflow builds binaries (macOS arm64, Linux musl, Windows x64) and publishes a GitHub release.
- shadcn components are vendored in `web/src/components/ui/` and drift from upstream; treat local edits there as the source of truth. The vendored `separator.tsx` uses `data-vertical:h-full` (not upstream's `data-vertical:self-stretch`): `self-stretch` overrides `items-center` and pins fixed-height separators (`data-[orientation=vertical]:h-4`) to the top of flex rows.
- Vendored components are trimmed to what the app actually uses — unused exports (and whole unused components/files) are deleted rather than kept for completeness. `sidebar.tsx`, `sheet.tsx`, `breadcrumb.tsx`, `tooltip.tsx`, `button.tsx` are subsets of upstream; re-adding a missing piece means porting it from upstream or `shadcn add` into a scratch dir and copying the needed part. Components import `cn` from the `cn` package directly; there is no `lib/utils.ts`, so `components.json`'s `utils` alias is vestigial.
